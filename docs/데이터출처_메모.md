## 1. iTunes Search API (오늘의 노래)
- 제공: Apple. 문서 https://performance-partners.apple.com/search-api
- 인증키: 필요 없음
- 쓰는 주소
  - 검색: `https://itunes.apple.com/search?term=…&country=US&media=music&entity=song&limit=5`
  - 다시 불러오기: `https://itunes.apple.com/lookup?id=…&country=US`
- **브라우저 직접 호출 확인**: 응답에 `Access-Control-Allow-Origin: *` 가 있어 GitHub Pages에서 바로 호출됨 → JSONP 대신 fetch 사용. 앨범 커버(mzstatic.com)도 같은 헤더라 이미지 저장에 커버가 들어감
- **country=KR 이 안 되는 문제 (직접 확인한 것)**: `country=KR` 로 검색하면 어떤 검색어든 결과가 0건. `lookup` 은 KR에서도 됨. `country=US` 로 검색하면 한국 노래(아이유 등)도 나옴. 그래서 검색·조회 모두 US 스토어 사용 → 곡명이 영어로 나오는 경우가 있음(예: 밤편지 → "Through the Night")
- 데이터 시점: 호출할 때마다 Apple에서 실시간으로 받음 (저장하지 않음)
- 이용 조건 요약 (문서 기준)
  - 호출 제한: 대략 **분당 20회** (바뀔 수 있음). → 검색은 입력 후 400ms 기다렸다가, 2자 이상일 때만 보냄
  - 미리듣기는 **스트리밍만** 가능, 내려받기·저장·캐시 금지 → 이 앱은 `<audio>` 로 재생만 함
  - 미리듣기를 쓸 때 iTunes 제공 표시가 필요 ("provided courtesy of iTunes") → 화면에 "노래 정보·미리듣기 제공: iTunes (Apple)" 문구, 곡마다 "Apple Music에서 보기" 링크(`trackViewUrl`)
  - 홍보 목적 콘텐츠로 쓰는 조건이 있음 (해당 곡을 알리는 용도, 다른 상품 홍보 금지 등) — 문서 원문 확인 권장
  - 자동 점검을 여러 번 돌렸을 때 실제로 검색 결과가 잠깐 비는 현상을 봄 → 제한에 걸린 것으로 추정

## 1-1. Deezer API (iTunes 검색이 실패할 때만 쓰는 예비 검색) — 2026-10-16 추가
- 왜 추가했나: **아이폰 브라우저(사파리·크롬 모두)에서는 Apple 이 iTunes 검색 요청에 데이터 대신 `301 → musics://…`(음악 앱 열기)를 돌려줌** → 브라우저가 결과를 못 읽음. Mac·iPad(데스크톱 모드)·안드로이드·PC는 정상. `lookup`(곡 ID로 다시 불러오기)은 아이폰에서도 정상. 직접 curl 로 아이폰 User-Agent 를 넣어 확인함
- 그런데 실제 아이폰(크롬)에서는 iTunes 검색이 되기도 함 (사용자 확인, 같은 날 시험용 아이폰 브라우저에서도 iTunes 결과가 나온 때가 있음) → 매번 같지 않음
- 그래서: **모든 기기에서 iTunes 를 먼저** 쓰고, 실패(연결·호출 제한·서버 문제·음악 앱으로 돌려보냄)할 때만 Deezer 로 한 번 더. Deezer 는 없는 곡(특히 한국 노래)이 꽤 많음 (사용자 확인)
- 검색 결과마다 "· iTunes" / "· Deezer" 로 출처를 작게 표시
- 제공: Deezer. 문서 https://developers.deezer.com/api , 이용 약관 https://developers.deezer.com/termsofuse
- 인증키: 필요 없음. 브라우저 직접 호출(CORS)은 막혀 있고 **JSONP(`output=jsonp`)로만** 받음. 앨범 커버(cdn-images.dzcdn.net)는 CORS 허용이라 이미지 저장에 들어감
- 쓰는 주소: 검색 `https://api.deezer.com/search?q=…&limit=5&output=jsonp` / 다시 불러오기 `https://api.deezer.com/track/{id}?output=jsonp`
- 링크에는 `s.p = "dz"` 로 출처를 표시 (없으면 iTunes). 받는 쪽은 출처에 맞는 곳에서 커버·미리듣기를 다시 불러옴
- 이용 조건 요약 (약관 기준, 직접 원문 확인 권장)
  - **비상업적 용도로만** 사용 가능, 이 앱으로 돈이나 대가를 얻으면 안 됨
  - Deezer 상표·로고는 허락된 방식으로만 사용 (이 앱은 로고 없이 "Deezer에서 보기" 글자 링크와 출처 문구만 씀)
  - 무료 이용자는 30초 미리듣기만 가능, 개인적 이용 범위
  - Deezer 가 언제든 접근을 제한·중단할 수 있음
  - 미리듣기 주소는 시간이 지나면 만료됨 → 링크에 저장하지 않고 열 때마다 다시 불러옴

## 1-2. 우리 서버 — Cloudflare Worker (2026-10-16 추가, 교수님 허락)
- 주소: `https://kreceipt-api.soom260.workers.dev` (코드: `worker/src/index.js`, 설정: `worker/wrangler.toml`)
- 하는 일: `/weather`(기상청 날씨), `/songs`·`/song`(iTunes 중계). 정해진 값만 받고, 허용한 화면 주소(soom260.github.io, 로컬 점검 주소)에서만 응답을 읽을 수 있음
- 배포: `.github/workflows/deploy-worker.yml` — `worker/` 가 바뀌면 GitHub Actions 가 wrangler 4.151.1 로 배포 (cloudflare/wrangler-action v4.1.3)
- **인증키 흐름**: 저장소 Settings → Secrets 의 `KMA_API_KEY`·`CLOUDFLARE_API_TOKEN`·`CLOUDFLARE_ACCOUNT_ID` → Actions 가 배포하면서 KMA 키를 Worker 비밀 값으로 넘김. 코드·화면·링크에는 키가 없음
- 무료 한도: 하루 요청 10만 번 (Cloudflare Workers 무료 플랜)
- **iTunes 중계 결과(직접 확인)**: Worker 에서 iTunes 를 부르면 대부분 `429 Too Many Requests` — Cloudflare 서버 주소를 다른 이용자와 같이 써서 Apple 호출 제한에 걸리는 것으로 보임. 그래서 노래 검색 순서는 ① 브라우저 직접 → ② Worker → ③ Deezer

## 1-3. 기상청 날씨 (공공데이터포털) — 2026-10-16 추가
- 제공: 기상청, 공공데이터포털(data.go.kr). 인증키 필요 (위 서버에만 있음)
- 쓰는 서비스
  - 기상청_단기예보 조회서비스 `VilageFcstInfoService_2.0` — 오늘: 초단기실황 `getUltraSrtNcst`(기온 T1H, 강수 형태 PTY), 초단기예보 `getUltraSrtFcst`(하늘 상태 SKY). 격자(nx, ny) 기준
  - 기상청_지상(종관, ASOS) 일자료 조회서비스 `AsosDalyInfoService/getWthrDataList` — 지난 날짜: 최고기온, 강수량, 평균 전운량, 적설. 관측소(stnIds) 기준
- 갱신: 초단기실황은 매시 정각 자료가 약 40분 뒤, ASOS 일자료는 다음 날 오전쯤 올라옴 → 어제 기록은 오전에 없을 수 있음
- 화면 표시 규칙: 오늘은 "지금 기온", 지난 날짜는 "그날 최고 기온". 날씨 이름은 강수 → 비/눈/비 또는 눈, 아니면 하늘 상태(맑음·구름 많음·흐림). 지난 날짜는 평균 전운량 0–5 맑음, 6–8 구름 많음, 9–10 흐림
- 이용 조건: 공공누리 등 공공데이터 이용 조건 — 출처(기상청) 표시. 개발계정은 서비스별 하루 호출 수 제한이 있음 (서버에서 오늘 30분·지난 날짜 7일 캐시)
- 관측소 번호 55곳은 2026-10-16 ASOS 응답의 관측소 이름(stnNm)과 모두 맞는지 확인함. 격자 변환은 서울시청 60,127 / 부산시청 98,76 / 제주시 53,38 로 기상청 기준값과 일치 확인

## 1-4. 위치 정보 처리 (GPS)
- "내 위치로 날씨 넣기"를 눌렀을 때만 위치 권한을 물음 (화면을 열 때 묻지 않음)
- 정확도 낮게(enableHighAccuracy: false) 받고, **브라우저 안에서 약 5km 격자 번호 + 가장 가까운 관측소 번호로 바꾼 뒤 좌표는 버림**. 서버에는 격자·관측소 번호만 감
- 링크·보관함에는 위치를 담지 않음. 날씨 결과(`맑음 21°`)만 담음 → 받는 사람은 서버를 다시 부르지 않음
- 위치를 거부하거나 지원하지 않으면 시·도(18곳) 고르기로 대신함

## 5. 개인정보·보안 관련 사실 (README에 쓸 수 있는 것)
- 캡처 이미지: 서버로 보내지 않음. 브라우저 안에서 읽은 뒤 버림 (`js/ocr.js` 에서 임시 주소 해제, 캔버스 비움)
- 인식된 원문 글자: 가게명·금액·날짜·시간만 뽑고 바로 버림. 잔액·계좌·카드번호는 화면에도, 링크에도 없음 (`js/parse.js`)
- 공유 링크에 담기는 것: 날짜, 고른 항목(이름·금액), 한마디, 보내는 사람 이름(선택), 노래 ID·곡명·가수 (`js/share.js`)
- 링크의 `#` 뒤 내용은 브라우저가 서버로 보내지 않음 → GitHub Pages 서버 기록에도 남지 않음
- 보관함·이름: 이 브라우저의 localStorage 에만 저장
- 인증키: 지금은 쓰는 API가 없음. 저장소 안에 키·토큰 없음 (`.env` 도 .gitignore 처리)
