# kreceipt — 영수증으로 쓰는 하루 기록


## 1. 목적

친구, 애인 간에 하루를 기록하고 공유하는 서비스는 많으나, 대부분 글 작성이나 영상 촬영 등 꾸준한 활동을 요구합니다. 이런 서비스는 초반엔 재밌게 느껴지거나 의욕적으로 하게 될지 몰라도 시간이 지날수록 소비자에게 피로감을 유발하여 얼마 안 지나 그만두게 됩니다.

그러나 소비는 매일 지속적으로 발생합니다. 소비 내역은 하루의 일상을 보여주며, 소비와 연관된 순간들을 자연스레 짚게 해줍니다. 따라서 기록의 단위를 결제 내역으로 잡아 소비자가 새로운 걸 쓰거나 찍는 부담감을 감소시키고, 결제내역에 노래, 감정, 한마디 등을 덧붙여 하루를 기록할 수 있도록 하였습니다.

가계부 목적의 앱이 아니라 합계나 예산, 지출 분류 등의 기능은 넣지 않았습니다. 최종 목적은 지출을 기록하는 게 아니라 그 날을 기록하고 공유하는 것입니다.

**전체 흐름**
결제내역 캡처 → 항목 확인·고르기 → 한마디·노래 등 추가 → 영수증 → 링크 공유 → 받은 사람이 열어 보관 → 보관함

## 2. 사용자
꾸준한 기록 서비스에 금방 지치는 20대. 
하루를 기록하고, 친구나 애인과 공유하고 싶지만 매일 글을 쓸 만큼은 아닌, 일기나 다이어리 앱을 써도 일주일 이내로 그만두는 2030을 타겟으로 하여 부담없이 가볍게 보내고 기록할 수 있는 영수증 형태의 기록을 제공합니다.

## 4. 사용법

실제 결제 캡쳐 내역이 없어도 실행해볼 수 있도록, 샘플 캡쳐를 넣어 구성했습니다.

1. 공개 주소에 들어가 **샘플 캡쳐로 해보기** 또는 **내 캡쳐로 만들기**를 누릅니다.
2. **확인하고 고르기**: 잘못 읽힌 글자를 고치고, 영수증에 넣을 항목만 체크합니다. 캡쳐 없이 직접 입력도 가능합니다.
3. **오늘의 기분, 날씨, 한마디와 노래**: 하루를 더 자세히 기록하기 위한 정보를 추가합니다. 모두 선택 사항이며, 없어도 영수증 발행이 가능합니다. 노래는 두 글자 이상 적으면 검색됩니다.
4. **영수증 만들기**를 누르면 영수증이 나옵니다. 나의 영수증은 보관함에 자동으로 저장됩니다.
5. **링크 보내기** 또는 **이미지 저장**을 통해 영수증 공유가 가능합니다. 공유된 링크를 다른 브라우저 또는 로컬 기기에서 열면 영수증을 확인하고 자신의 보관함에 저장하거나, 영수증 주인에게 답장을 보낼 수 있습니다. 칸에 친구 이름을 적으면 내 보관함에서 그 이름으로 묶입니다. 링크에 보낸 사람 이름이 들어 있으면 미리 이름이 채워져 있습니다.(수정 또한 가능합니다.)
6. **인스타 스토리로 보내기**를 통해 인스타그램 즉시 업로드가 가능합니다. 인스타 스토리로 보내기 버튼을 눌러 뜨는 공유 창에서 인스타그램을 택하면 릴스 / 게시물/ 스토리 / 메시지 중 하나를 택해 업로드할 수 있습니다. 공유 창에서 다른 앱(문자, 타 SNS)를 선택해도 업로드가 가능합니다.
7. 또는 **스티커로 복사** 버튼을 누르면 배경이 투명한 영수증 PNG가 클립보드에 복사됩니다. 인스타 스토리에서 붙여넣기를 통해 간편하게 영수증 PNG를 스토리에 부착할 수 있으며, 인스타 메시지 / 타 앱에서도 붙여넣기를 통해 이미지 전송 또는 업로드가 가능합니다. 

**상태 다시 보기**

로딩, 실패, 빈 결과 같은 화면은 확인이 가능케 하고자 주소에 조건을 붙이면 그 상황을 흉내 내도록 해 두었습니다.

주소를 열기만 하면 첫 화면은 똑같고, 열은 뒤 아래 "해 볼 것"까지 해야 상태가 보입니다. 

| 주소에 붙일 것 | 해 볼 것 | 보이는 상태 |
|---|---|---|
| `?sim=slow` | 샘플 캡처로 해보기, 노래 검색, 날씨 | 로딩이 3초 더 길게 보임 |
| `?sim=error` | 샘플 캡처로 해보기, 노래 검색, 날씨 | 실패 안내 |
| `?sim=empty` | 샘플 캡처로 해보기, 노래 검색 | 결과 없음 안내 |
| `?sim=nostorage` | 영수증 만들기, 보관함 열기 | 보관함을 쓸 수 없다는 안내 |
| `#r=abc123` | 열기만 하면 됨 | 손상된 링크 안내 |
| `?debug=1` | 아무 기능이나 | 화면 구석에 지금 화면 상태 칩 |

## 5. 데이터 출처와 갱신일

| 출처 | 어디에 쓰나 | 조건 | 갱신 |
|---|---|---|---|
| 기상청 초단기실황·ASOS 일자료 (공공데이터포털) | 영수증에 찍히는 날씨 | 인증키 有(서버에 둠) | 호출 시점 기준. 서버가 오늘 날씨는 30분, 지난 날짜는 7일 동안 캐시 |
| iTunes Search API (Apple) | 오늘의 노래 검색 | 키 없음, 분당 약 20회 | 호출할 때마다 실시간 |
| Deezer API | iTunes 검색이 실패할 때만 대신 사용 | 키 없음, 비상업적 용도만 | 호출할 때마다 실시간 |
| Tesseract.js 7.0.0 + 한국어·영어 데이터 | 캡처 글자 인식 | 사이트 안에 포함 | 버전 고정 |
| lz-string 1.5.0 | 영수증 내용을 링크에 압축 | 사이트 안에 포함 | 버전 고정 |
| html-to-image 1.11.13 | 영수증 이미지 저장 | 사이트 안에 포함 | 버전 고정 |

- 샘플 캡처는 직접 만든 가상 데이터입니다.
- 
- 인증키: 기상청 키는 GitHub Secrets에만 두었습니다. GitHub Actions 가 서버(Cloudflare Worker) 배포 때 비밀 값으로 넘기며, 이외 키 노출은 없습니다.
- 답장 스티커: 서버(KV)에 영수증 해시 번호·스티커·이름(선택)·시각만 90일 저장, 영수증 내용은 저장 안 함
- 친구별로 보기: 받을 때 적은 이름으로 묶음 (사용한 브라우저 안 한정)
- 위치: 누를 때만 묻고 좌표는 저장하지 않습니다. 링크에는 날씨 결과만 나옵니다.
- 날씨: 기상청 (오늘=초단기실황, 지난 날짜=ASOS 일자료). 호출 시점 기준, 서버에서 오늘 30분·지난 날짜 7일 캐시를 저장합니다. 실시간 호출이 필요하여 구현 중 서버를 구축하여 연결했습니다.
- 캡처는 업로드하지 않으며, 가게명·금액·시간만 뽑습니다. 링크 `#` 뒤 내용은 서버로 가지 않고, 보관함은 내 브라우저에만 저장됩니다.

## 7. 알려진 한계

**금융 연동 대신 캡처**
금융앱·마이데이터·오픈뱅킹 연동은 개인정보 침해 우려가 있어. 대신 결제내역 화면 내역 캡쳐로 방향성을 수정했습니다. 다만 따라서 읽을 수 있는 형식이 제한됩니다. 한 거래가 "가게명 + 금액(-4,500원)" 줄과 "시간" 줄로 이루어진 목록이어야 하고, 날짜 줄은 "10월 10일 토요일", "2026.10.10", "10.10 (토)" 중 하나여야 합니다. 입금(+)·환불·취소 줄과 잔액·한도는 읽지 않습니다.
가게 아이콘을 글자로 잘못 읽는 걸 지우는 과정에서, 가게명이 한 글자 + 띄어쓰기로 시작하면(예: "더 카페") 앞 글자가 같이 빠질 수 있는 문제도 있습니다. 이는 사용자가 확인 단계에서 직접 고쳐야 합니다.

**노래 검색**
한국(KR) 스토어 검색이 안 돼서 미국(US) 스토어를 쓰도록 하였습니다. 그래서 한국 곡보다 외국 곡이 더 서치가 잘 되고, 제목이 영어로 나오는 경우가 있습니다.
아이폰 상의 노래 검색의 경우, Apple이 아이폰 브라우저의 iTunes 검색을 음악 앱으로 돌려보내고, 서버(Cloudflare)를 거쳐 부르는 것도 429/403으로 막아 Itunes 검색이 불가능할 때가 있습니다. 지금은 이럴 때 Deezer로 대신 찾는데, Deezer에는 한국 노래가 적고 비상업적 용도로만 쓸 수 있어 한계가 존재합니다. 9주차에 Vercel로 옮기면서 iTunes를 중계해 고칠 계획입니다. 

**날씨**

어제 날씨 기록은 기상청에 다음 날 오전쯤 올라와서, 그 전에는 불러오기가 안 됩니다. 위치는 관측소 55곳 중 가장 가까운 곳 기준으로 기재합니다.

**보관함과 친구**
보관함은 브라우저마다 따로 저장됩니다. 카톡 안 브라우저와 크롬은 서로 다른 보관함이고, 브라우저 데이터를 지우면 사라지는 문제가 있습니다. 옮기려면 내보내기/가져오기를 써야 합니다.
친구 추가·받은 함·로그인이 없어서, 친구별 보기는 보관할 때 내가 적은 이름 기준으로 묶입니다. 같은 친구라도 이름을 다르게 적으면 따로 묶입니다. 적은 이름은 나중에 못 바꾸고, 지운 뒤 다시 보관해야 합니다.

**공유&이미지**
링크를 가진 사람은 누구나 볼 수 있고, 한 번 보낸 링크는 회수할 수 없습니다. 링크 미리보기 이미지는 모든 영수증이 같은 것 하나를 씁니다.
답장 스티커도 링크만 있으면 누구나 남기고 볼 수 있습니다. 영수증 하나에 30개까지가 제한입니다.
이미지로 저장하면 웹 글꼴 대신 기기 글꼴로 그려집니다. 휴대전화는 이미지를 띄운 뒤 꾹 눌러 저장하는 방식입니다.
인스타 스토리에 바로 올리는 건 웹에서는 안 됩니다. "스토리로 보내기"(공유 창)와 "스티커로 복사"(클립보드)로 대신했습니다. 클립보드 이미지 복사는 아이폰에서 가장 잘 되고, 안드로이드는 키보드·기기마다 다르며, 카카오톡 안 브라우저에서는 막힐 수 있습니다.
카카오톡의 "외부 브라우저로 열기"는 기기나 버전에 따라 불가할 가능성이 존재합니다.


## 8. 사용한 자료와 AI 도움

참고한 자료는 수업 자료와 공공데이터포털 기상청 API 활용 가이드, Apple iTunes Search API 문서, Deezer API 문서, Tesseract.js·lz-string·html-to-image 공식 README입니다.

서비스의 기획(서비스의 기능 전반, 금융앱과의 직접 연동 없이 캡쳐 내역을 확인하여 기입하는 것, iTunes의 사용, 화면 상태, 범위 밖 목록 등)은 제가 확인했습니다. 또한 기능을 업데이트할 때마다 오류가 나는 부분이 있는지 매번 직접 확인하고 수정 및 개선을 진행했습니다.

AI의 도움을 받은 부분은 다음과 같습니다.
코드 대부분은 Claude code(Claude opus 5.5)의 도움을 받았습니다.
화면(index.html, css/style.css)과 js/ 아래 기능 코드 전부, 서버 코드(worker/)와 GitHub Actions 자동 배포, 자동 점검 도구(tools/check-states.mjs, tools/check-flow.mjs), 샘플 캡처, docs/의 문서 초안은 AI가 썼습니다. 특히 노래 검색 부문에서 ios에서 iTunes를 쓸 때 오류가 나는 문제를 해결하기 위해 deezer을 사용하는 등의 해결책에 있어 AI의 도움을 받았습니다.
